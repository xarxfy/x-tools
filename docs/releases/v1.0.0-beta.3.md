> **X-TOOLS is entirely “vibe coded”** (written with an AI assistant) and has had no independent security audit.
> This is a **beta** – install it on a **separate test VM or LXC (not on the Proxmox host)**, keep backups.

**Install** (as root, on a Debian/Ubuntu VM or LXC with internet access):

```sh
curl -fsSL https://raw.githubusercontent.com/xarxfy/x-tools/main/install.sh | sudo XT_REF=v1.0.0-beta.3 bash
```

**Update from beta.1/beta.2:** `sudo x-tools-ctl update`, then log in again. Servers you want to administer (updates, users, firewall) need a new install command once.
**Remove:** `curl -fsSL https://raw.githubusercontent.com/xarxfy/x-tools/main/uninstall.sh | sudo bash`

### What is new
- **Roles with free permissions** and a new **Administration** area (users, roles, audit log, system, notifications, Cloudflare, backup) – only visible to people with the matching permissions.
- **Server groups and tags** (free names), a **server list** with a page and tabs per server, maintenance windows and update runs per group or tag.
- **New menu**: *Infrastructure* (Servers, Proxmox, Docker), *Manage* (Services, Domains, Customers), *Monitoring*; logins are a tab of *Services*, DNS/tunnels a tab of *Domains*, your account sits behind your name.
- **Agents** are added and managed on the page of their kind; operators may do it.
- Wide screens use their width; fixes for the server administration (writable agent service, error messages behind Cloudflare).

Full list: [CHANGELOG](https://github.com/xarxfy/x-tools/blob/main/CHANGELOG.md). Try the server administration (updates, users, firewall) on an unimportant test server first.
